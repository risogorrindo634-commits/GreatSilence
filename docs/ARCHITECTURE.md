# 架构

> v1.0 · 2026-11-11。对应 [游戏设计文档](GDD.md) 和 [垂直切片规格](SLICE.md)。

## 1. 原则

1. **内核是纯的。** 模拟内核不碰界面、时钟和网络。随机数由种子驱动，状态可以整体序列化。同一个种子加同一串操作，永远得到同一个结果。
2. **真相只在内核里。** 界面拿到的是一份去掉了真相的视图。只有结局时才揭开。
3. **内容是数据。** 真相、星系、签字事项、数值都放在 `content/`，改它们不用动逻辑。
4. **模型只负责措辞。** 它拿到事实，产出文字，不能改变状态。每一处都有模板兜底。
5. **先简单。** 一个包，不引入界面框架。等复杂到需要时再拆。

## 2. 分层

```
content   数据：真相、星系、签字事项、数值
   |
core      确定性的模拟：状态、操作、规则、结局
   |
app       界面与绘制：星图、星系、风景、科研、朝堂、推理板   （未开始）
   |
ai        文书的措辞：模板，之后接入模型                     （未开始）
```

依赖只能自上而下。`core` 不得引用 `app` 和 `ai`。

## 3. 内核的接口

```ts
createGame(seed, truth?) -> GameState
can(state, action) -> string | null     // 不能做时返回原因
reduce(state, action) -> GameState      // 不修改传入的状态
publicView(state) -> PublicView         // 给界面用，不含真相
```

- 所有玩法都是一个操作：观景、勘察、采集、建阵列、弹弓、调谐、发射探测器、裁决、启航、调整科研、下结论。
- 两种时间在内核里是两个函数：花清醒日，和让世界过去若干年。后者负责能源、科研、探测器抵达和命运的结算。
- 命运是一个由状态算出来的值，不单独存储，所以不会和别的数值对不上。

## 4. 存档与重放

状态是一个可以直接转成 JSON 的对象。存档就是存它。因为内核是确定性的，也可以只存种子和操作序列来重放，用于调试和复盘。

## 5. 模型的位置

灰盒阶段不接入模型，文书用模板。接入时遵守：

- 给模型的输入只包含它扮演的角色该知道的事实，不含真相。
- 输出要过结构校验，失败时退回模板。
- 高频的问答用小模型，报告和评语用较强的模型，走供应商适配层。

## 6. 测试

| 测试 | 保证什么 |
|---|---|
| 确定性 | 同一个种子和操作序列得到完全相同的状态 |
| 视图不泄密 | 给界面的视图里没有真相 |
| 证据可区分 | 任意两种真相至少有两类证据不同 |
| 两种时间 | 亲自做只花清醒日，交给 AI 只花世界年 |
| 命运的驱动 | 同样的操作在不同真相下命运不同，且符合权重 |
| 可通关 | 每种真相都有一条走到"明断"的路线 |
| 结局表 | 每个结局的条件各有一个用例 |

## 8. 技术选型

- TypeScript，严格模式。
- Vitest 做测试。
- 界面开始时加入 Vite，绘制用 Canvas，暂不引入框架。
- 部署是纯静态站点。
